# نظام كوبونات المشرفون للحج والعمرة — توليد QR وكشفه

موقع كامل لتوليد كوبونات خصم بتصميم الحملة، كل كوبون يحمل رمز QR فريداً، مع صفحة
كشف تتأكد أن الكوبون **مولّد من هذا الموقع** وأنه **لم يُستخدم من قبل**، وزر
«تم الإستخدام» لتسجيل الاستخدام.

> A complete coupon site for the Moshrefoon Hajj & Umrah campaign: batch QR
> generation on the campaign artwork, a scanner/verifier that proves a coupon was
> issued by this site, and one-tap redemption. Arabic RTL interface throughout.

---

## المميزات

| | |
|---|---|
| **توليد بالجملة** | اطلب أي عدد (مثلاً ١٠ أكواد) فيولّدها الموقع دفعة واحدة برقم دفعة خاص |
| **تصميم الحملة** | الكوبون يُرسم على تصميم الحملة الأصلي، ورمز QR تحت شعار الحملة في اليسار |
| **حفظ الأكواد** | كل كود يُحفظ في قاعدة بيانات SQLite للرجوع إليه عند الكشف |
| **كشف موثّق** | كل كود موقّع بتوقيع HMAC، فأي رمز لم يُولَّد من الموقع يظهر فوراً كـ«توقيع غير صالح» |
| **زر «تم الإستخدام»** | بضغطة واحدة يُسجَّل استخدام الكوبون، ولا يمكن استخدامه مرة أخرى |
| **قارئ كاميرا** | مسح الرمز من كاميرا الجوال مباشرة، أو إدخال الرقم يدوياً |
| **تنزيل وطباعة** | تنزيل الكوبون PNG، أو الدفعة كاملة ZIP، أو ورقة A4 جاهزة للطباعة (٨ كوبونات في الصفحة) |
| **سجل كامل** | سجل لكل عملية كشف: التاريخ، النتيجة، المستخدم |
| **صلاحية وإلغاء** | تاريخ انتهاء اختياري، وإلغاء أي كوبون أو التراجع عن استخدامه |

## التشغيل

```bash
npm install
cp .env.example .env      # عدّل PUBLIC_URL و ADMIN_PASSWORD
npm start
```

ثم افتح <http://localhost:3000>.

إذا لم تضع `ADMIN_PASSWORD` في `.env` فسيولّد النظام كلمة مرور عشوائية عند أول
تشغيل، ويطبعها في الطرفية ويحفظها في `data/admin-password.txt`.

**مهم:** اضبط `PUBLIC_URL` على العنوان الحقيقي للموقع **قبل** توليد أي كوبونات،
لأن هذا العنوان يُكتب داخل رمز QR، وتغييره لاحقاً لا يغيّر الرموز المطبوعة.

المتطلبات: Node.js 22.5 أو أحدث (يستخدم `node:sqlite` المدمج — لا حاجة لأي قاعدة
بيانات خارجية).

## طريقة العمل

1. **لوحة التحكم** ← اكتب عدد الأكواد (١٠ مثلاً) واضغط «توليد الأكواد».
2. تظهر الكوبونات مباشرة: حمّلها PNG أو ZIP، أو اطبع الدفعة على ورق A4.
3. عند العميل: **صفحة الكشف** ← شغّل الكاميرا وامسح الرمز (أو اكتب الرقم يدوياً).
4. تظهر النتيجة: **كوبون صالح** / **مستخدم مسبقاً** / **غير معروف** / **توقيع غير صالح**.
5. بعد تسليم الخصم اضغط **«تم الإستخدام»** — يُغلق الكوبون نهائياً.

مسح الرمز بكاميرا الجوال العادية يفتح صفحة الكشف مباشرة على نفس الكوبون، ويستطيع
العميل التأكد من صحة كوبونه بنفسه دون تسجيل دخول (بدون أن يرى التوقيع أو الرابط).

## كيف يعرف الموقع أن الكوبون منه؟

لكل كوبون طبقتان من التحقق:

1. **التوقيع (HMAC-SHA256).** الرابط داخل الرمز هو
   `https://موقعك/v/MSH-XXXX-XXXX.TTTTTT` حيث `TTTTTT` توقيع مشتق من الكود ومن
   المفتاح السري في `data/secret.key`. من لا يملك المفتاح لا يستطيع تركيب رمز
   صحيح، حتى لو عرف شكل الأكواد.
2. **قاعدة البيانات.** يجب أن يكون الكود مسجّلاً فعلاً وحالته `active`.

النتيجة `forged` تعني أن الرمز لم يخرج من هذا الموقع، و`unknown` تعني أن الرقم غير
مسجّل أصلاً. الصفحة العامة لا تكشف التوقيع ولا رابط الرمز لغير المسجّلين، فلا
يمكن تحويل رقم مسرّب إلى كوبون عامل.

> ⚠️ احتفظ بنسخة من `data/secret.key` — تغييره يُبطل توقيع كل الكوبونات المطبوعة.

## واجهة البرمجة (API)

| الطريقة | المسار | الوصف |
|---|---|---|
| `POST` | `/api/login` | تسجيل الدخول (`{ password }`) |
| `POST` | `/api/batches` | توليد دفعة: `{ quantity, amount, note, expiresAt }` |
| `GET` | `/api/batches` · `/api/batches/:ref` | الدفعات وكوبوناتها |
| `GET` | `/api/batches/:ref/export.csv` | تصدير الدفعة CSV |
| `GET` | `/api/coupons?status=&batch=&q=` | بحث وتصفية |
| `GET` | `/api/coupons/:code` | تفاصيل كوبون مع سجل الكشف |
| `GET` | `/api/coupons/:code/qr.png` · `qr.svg` | رمز QR كصورة |
| `POST` | `/api/coupons/:code/redeem` | **تم الإستخدام** |
| `POST` | `/api/coupons/:code/restore` · `/void` | تراجع · إلغاء |
| `GET` | `/api/verify?token=…` | الكشف (عام، يقبل الرابط أو الكود) |

مثال:

```bash
curl -c c.txt -X POST localhost:3000/api/login \
     -H 'Content-Type: application/json' -d '{"password":"..."}'

curl -b c.txt -X POST localhost:3000/api/batches \
     -H 'Content-Type: application/json' -d '{"quantity":10,"amount":"10"}'

curl 'localhost:3000/api/verify?token=MSH-7K3D-9QF2.A1B2C3'
```

## أين أفتح الموقع؟ (النشر)

الموقع خادم Node، لذلك لا يكفي رفعه على GitHub وحده — GitHub Pages تستضيف
صفحات ثابتة فقط. اختر واحدة من الطرق التالية، وكلها جاهزة في هذا المجلد.

### ١) على جهازك (للتجربة فوراً)

```bash
npm install && npm start
```

ثم <http://localhost:3000>. الكاميرا تعمل على localhost بدون HTTPS.

### ٢) Railway — بضغطات من المتصفح

1. [railway.com](https://railway.com) → **New Project → Deploy from GitHub repo** واختر
   المستودع. سيبني من `Dockerfile` تلقائياً (`railway.json` يضبط الباقي).
2. **Settings → Networking → Generate Domain** للحصول على عنوان الموقع.
3. **Variables**: أضف `ADMIN_PASSWORD` (كلمة مرور لوحة التحكم). ولا حاجة إلى
   `PUBLIC_URL` ولا `TRUST_PROXY` — يقرأ التطبيق عنوان Railway وحده.
4. **Volume** (مهم جداً): أضف حجماً دائماً بمسار **`/app/data`**. بدونه تُفقد
   الكوبونات ومفتاح التوقيع مع كل إعادة نشر.
5. افتح العنوان وسجّل الدخول، ثم ابدأ التوليد.

عند ربط نطاقك الخاص لاحقاً أضف متغير `PUBLIC_URL` بعنوانك الجديد — لكن انتبه:
الكوبونات المطبوعة قبل ذلك تحمل العنوان القديم داخل رمز QR.

الحجم الدائم يحفظ `data/coupons.db` و `data/secret.key`، فيبقى توقيع الكوبونات
صالحاً عبر عمليات النشر. ولمزيد من الأمان أضف `COUPON_SECRET` كمتغير ثابت.

### ٣) Render — بديل مشابه

1. ادفع الكود إلى GitHub (تم بالفعل).
2. في Render: **New → Web Service** واختر المستودع.
3. **Build**: `npm ci --omit=dev` · **Start**: `npm start` (اترك Root Directory فارغاً).
4. من **Environment** أضف: `ADMIN_PASSWORD` و `COUPON_SECRET` (أي نص عشوائي طويل)
   و `TRUST_PROXY=1`، ثم `PUBLIC_URL` بعنوان الخدمة بعد أول نشر
   (مثل `https://moshrefoon-coupons.onrender.com`).
5. أضف **Disk** بمسار `/var/data` واضبط `DB_PATH=/var/data/coupons.db` حتى
   تبقى الكوبونات بعد إعادة التشغيل. (الخطة المجانية بلا قرص دائم — الكوبونات
   تُفقد عند إعادة النشر، فاستخدمها للتجربة فقط.)

ملف `render.yaml` في جذر المستودع يفعل ذلك كله دفعة واحدة عبر **Blueprint**
بدل الإنشاء اليدوي.

### ٤) Fly.io — مع قرص دائم

```bash
fly launch --copy-config --no-deploy      # يقرأ fly.toml الموجود
fly volumes create coupon_data --size 1
fly secrets set ADMIN_PASSWORD=... COUPON_SECRET=...
fly deploy
```

عدّل `PUBLIC_URL` في `fly.toml` إلى عنوان تطبيقك قبل توليد أي كوبونات.

### ٥) أي خادم فيه Docker (VPS)

```bash
# عدّل PUBLIC_URL و ADMIN_PASSWORD في docker-compose.yml
docker compose up -d
```

قاعدة البيانات ومفتاح التوقيع في حجم `coupon-data` الدائم. ضع nginx أو Caddy
أمامه لشهادة HTTPS.

### قبل الإطلاق

- **HTTPS ضروري** لعمل الكاميرا في المتصفح (إلا على localhost).
- **اضبط `PUBLIC_URL` قبل توليد أي كوبونات** — العنوان يُطبع داخل رمز QR.
- **احفظ `COUPON_SECRET`** (أو ملف `data/secret.key`): تغييره يُبطل توقيع كل
  الكوبونات المطبوعة.
- خذ نسخة احتياطية دورية من `data/coupons.db`.
- اجعل اسم النطاق قصيراً: كلما طال الرابط زادت كثافة رمز QR.
